# 雷达全栈仿真平台初版设计

## 1. 目标

构建一个面向雷达算法研究和开发人员的 Python 仿真代码库。平台从发射复数基带波形开始，经过目标与航迹、单站传播、接收前端、距离/速度处理和 CFAR 检测，输出可复现的中间数据、检测结果及诊断图。

初版支持 FMCW 和脉冲 LFM 两条信号链，实际运行限制为 1T1R，但数据形状和模块接口不得隐去发射端，也不得把单通道假设固化到核心算法中。

## 2. 用户与交互方式

平台面向能够直接阅读和修改 Python 的算法研究人员，不提供 GUI、Web 服务、数据库或 YAML 配置。用户通过编辑 Python 配置模块，或在实验脚本中构造 dataclass 配置对象来改变参数。

标准示例入口为：

```powershell
python examples/run_fmcw.py
python examples/run_lfm.py
```

## 3. 技术约束

- Python 3.11 或更高版本。
- NumPy 负责数组和复信号计算。
- SciPy 负责窗函数、匹配滤波及必要的信号处理功能。
- Matplotlib 负责静态诊断图。
- pytest 负责自动测试。
- 核心算法不依赖图形界面或 notebook 状态。
- 所有含随机性的计算都必须支持显式随机种子。

## 4. 坐标系与符号约定

雷达默认位于世界坐标原点 `(0, 0, 0)`，波束朝向 `+X`。采用右手直角坐标系：

- 方位角 `0°` 指向 `+X`。
- 方位角 `-90°` 指向 `+Y`。
- 方位角 `+90°` 指向 `-Y`。
- 俯仰角 `+90°` 指向 `+Z`。
- 距离为雷达到目标的三维斜距。
- 径向速度以远离雷达为正。

坐标变换定义为：

```python
azimuth = atan2(-y, x)
elevation = atan2(z, hypot(x, y))

x = range_m * cos(elevation) * cos(azimuth)
y = -range_m * cos(elevation) * sin(azimuth)
z = range_m * sin(elevation)
```

方位角规范化到 `[-180°, 180°)`。目标在原点时方位角和俯仰角没有物理定义，坐标转换函数必须拒绝零距离极坐标计算。

对位置向量 `p` 和速度向量 `v`，径向速度为：

```text
vr = dot(p, v) / norm(p)
```

单站多普勒频率使用：

```text
fd = -2 * vr / wavelength
```

因此远离雷达的目标具有负物理多普勒频率；处理结果的速度轴再转换为“远离为正”的显示约定。

## 5. 总体架构

平台使用显式信号链和复数基带计算：

```text
Config
  -> Waveform
  -> Transmitter
  -> Propagation(Scene + Targets + Trajectories)
  -> Receiver Frontend
  -> RawDataCube
  -> Range Processing
  -> Doppler Processing
  -> 2-D CA-CFAR
  -> DetectionResult + Saved Artifacts
```

各层只通过明确的数据对象通信。处理链只读取接收信号和采样元数据，不读取目标真值。目标真值只用于实验评价、测试和结果对照。

## 6. 模块边界

### 6.1 `config`

提供带类型注解和验证逻辑的 dataclass：

- `RadarConfig`：雷达位置、姿态、载频、发射功率、Tx/Rx 数量和标量天线增益。
- `FMCWConfig`：带宽、Chirp 时长、Chirp 重复周期、采样率、每帧 Chirp 数和帧数。
- `LFMConfig`：带宽、脉冲宽度、PRI/PRF、采样率、每帧脉冲数和帧数。
- `SceneConfig`：目标集合与仿真起止时间。
- `NoiseConfig`：热噪声参数或直接复基带噪声功率，以及随机种子。
- `ProcessingConfig`：窗函数、距离/多普勒 FFT 点数和 CFAR 参数。
- `OutputConfig`：实验名称、输出目录及需要保存的数据产品。

配置验证在大规模数组分配前执行。非法采样率、非正物理参数、非递增航迹时间、仿真时间超出航迹覆盖范围、FFT 点数小于输入长度和不合法 CFAR 窗口均抛出包含参数名称的异常。会发生距离或速度混叠但仍可计算的配置发出警告。

初版运行时验证 `num_tx == 1` 且 `num_rx == 1`。这项限制位于配置验证层，不得通过删除通道轴来实现。

### 6.2 `geometry`

负责：

- XYZ 与距离/方位/俯仰的双向转换。
- 斜距、视线单位向量和径向速度计算。
- 角度规范化。
- 上述坐标和速度符号约定的集中实现。

其他模块不得重复实现坐标公式。

### 6.3 `scene`

每个目标包含唯一 ID、名称、恒定 RCS（dBsm）和一组带时间戳的航迹点。航迹点输入支持以下两种形式：

- 笛卡尔坐标 `(time_s, x_m, y_m, z_m)`；
- 极坐标 `(time_s, range_m, azimuth_deg, elevation_deg)`。

载入时将所有航迹点转换为 XYZ，并在 XYZ 空间做分段线性插值，以避免角度跨越 `±180°` 时发生错误插值。当前线段的斜率作为该段速度；在内部航迹节点上采用右侧线段速度，最后一个节点采用左侧线段速度。

仿真时间必须完全落在每个目标的航迹时间范围内，不做静默外推。RCS 在整个仿真期间保持恒定，不实现 Swerling 起伏。

### 6.4 `waveforms`

定义统一的波形接口，显式生成复数基带波形、快时间轴、慢时间轴和处理所需元数据。

FMCW 初版使用重复的线性上扫频 Chirp。波形层生成未去斜的发射基带信号；接收前端使用同一波形对象生成本振参考并完成去斜。不得把“直接生成拍频矩阵”作为唯一实现。

脉冲 LFM 初版使用线性调频矩形包络脉冲。波形对象同时提供匹配滤波参考信号。

发射信号的规范张量形状为：

```text
[frame, slow_time, tx, fast_time]
```

当前 Tx 维长度为 1。未来 TDM-MIMO 可在不同慢时间索引激活不同 Tx，FDM/CDM 可通过波形或编码对象区分，而无需改变场景层接口。

### 6.5 `channel`

对每个 Tx–目标–Rx 路径计算并相干叠加：

1. 目标在采样时刻的位置和速度；
2. 双程传播时延；
3. 分数采样延迟；
4. 单站多普勒相位；
5. 由发射功率、天线增益、波长、距离和 RCS 决定的复振幅；
6. 所有目标的复回波；
7. 复高斯白噪声。

使用单站雷达方程确定接收功率：

```text
Pr = Pt * Gt * Gr * wavelength^2 * sigma /
     ((4*pi)^3 * R^4)
```

复基带振幅为接收功率平方根，并包含传播相位。`sigma` 由 dBsm 转换为平方米。初版不包含天线方向图、多径、遮挡、地杂波和大气衰减。

接收信号的规范张量形状为：

```text
[frame, slow_time, rx, fast_time]
```

物理 Rx 信号不保留不可直接观测的 Tx 维。未来 MIMO 的 Tx 分离发生在接收后的专用解码层，解码结果可形成虚拟通道维。

### 6.6 `frontend`

- FMCW：将接收复基带信号与发射参考信号去斜，输出拍频数据立方体。
- LFM：保留接收复基带脉冲，提供匹配滤波处理所需参考和有效采样区间。

前端必须保留帧、慢时间、接收通道和快时间维及对应元数据。

### 6.7 `processing`

FMCW 处理顺序：

1. 去斜数据快时间加窗；
2. 距离 FFT 和有效频率区间选择；
3. 慢时间加窗；
4. Doppler FFT 与 `fftshift`；
5. 功率距离–多普勒图；
6. 二维 CA-CFAR；
7. 局部峰值筛选与检测列表生成。

LFM 处理顺序：

1. 接收脉冲匹配滤波和距离压缩；
2. 有效距离门选择；
3. 慢时间加窗；
4. Doppler FFT 与 `fftshift`；
5. 功率距离–多普勒图；
6. 二维 CA-CFAR；
7. 局部峰值筛选与检测列表生成。

处理器根据波形和采样参数计算距离轴、速度轴、理论分辨率及最大无模糊范围/速度。FFT 点数、窗函数和零填充由配置控制。

二维 CA-CFAR 使用矩形训练区和保护区。边缘处因训练单元不完整而不做判决，并在门限图中标记为无效。门限缩放由实际训练单元数和配置虚警率计算。CFAR 输出检测掩码、门限图和噪声估计图。

相邻命中单元经过局部最大值筛选后生成 `Detection`，字段包括帧索引、距离、径向速度、功率、噪声估计和估计 SNR。1T1R 检测结果不包含估计方位角或俯仰角。

### 6.8 `results`

提供统一数据对象：

- `SignalCube`：复信号数组、维度名称、时间轴和波形元数据。
- `RangeDopplerResult`：复数谱、功率图、距离轴和速度轴。
- `CFARResult`：检测掩码、门限图和噪声估计图。
- `Detection`：单个结构化检测结果。
- `SimulationResult`：原始数据、中间处理结果、检测列表和目标真值。

示例默认写入：

```text
outputs/<experiment_name>/
  config.json
  truth.csv
  detections.csv
  raw_data.npz
  range_profile.png
  range_doppler.png
  cfar_map.png
```

图像和 CSV 是面向研究人员的诊断产物，不是模块之间的数据接口。

## 7. 数据流与时间模型

每帧包含多个 Chirp 或脉冲。波形层给出每个快时间样本的绝对采样时刻，场景层在这些时刻求目标状态。通道层由时变斜距生成延迟和相位，不把整个 CPI 内的目标状态冻结为一个常量。

初版采用复数基带等效模型，不对 GHz 载频直接采样。载频仍参与波长、多普勒和传播相位计算。实现允许在不改变公开接口的前提下，为 FMCW 增加解析加速后端，但显式发射信号链必须保留并作为行为基准。

## 8. 噪声模型

支持两种互斥配置方式：

1. 直接给定接收复基带噪声功率；
2. 根据温度、噪声系数和等效噪声带宽计算热噪声功率。

若两种方式同时提供则报配置错误。噪声为零均值圆对称复高斯白噪声，实部和虚部各承担总噪声功率的一半。随机数生成器由 `NoiseConfig.seed` 创建，不使用隐式全局随机状态。

## 9. 测试策略

测试验证平台的物理关系、接口行为和基础处理链对理想单目标的定位能力。

### 9.1 单元测试

- 坐标变换在非零距离输入上的往返一致性和轴向特例。
- 航迹点时间排序验证、XYZ 插值、节点速度约定和范围外错误。
- FMCW 和 LFM 基带相位与时间轴。
- 分数延迟和多普勒符号。
- 固定随机种子的可复现性及复噪声统计量。
- 人工功率矩阵上的 CA-CFAR 门限、边缘行为和检测掩码。

### 9.2 物理关系测试

- 静止目标的双程时延等于 `2R/c`。
- 给定径向速度的慢时间相位增量符合理论多普勒。
- 接收功率与线性 RCS 成正比，并随距离近似按 `R^-4` 变化。
- FMCW 去斜信号的拍频关系符合所配置的调频斜率和时延。
- LFM 匹配滤波响应与所生成的发射参考一致。
- 在无噪声、单目标且目标参数位于波形无模糊范围内的场景中，距离峰值和速度峰值必须分别落在理论真值所在的一个距离分辨单元和一个速度分辨单元内。

上述峰值测试使用平台根据实际波形、观测时长和处理参数计算的理论分辨率作为容差，不要求目标恰好位于 FFT 栅格中心。

### 9.3 端到端测试

FMCW 和 LFM 各运行一个尺寸较小的双目标场景，验证：

- 全链路可运行；
- 数据维度和各坐标轴长度一致；
- 输出为有限数值且可序列化；
- CFAR 结果结构和输出文件完整；
- 处理链未读取场景真值。

CFAR 算法正确性仍由独立的人工功率矩阵测试保证，避免把检测门限行为与无噪声单目标的峰值定位测试混为一体。

## 10. 初版范围

初版包含：

- 多目标和分段线性三维航迹；
- XYZ 或极坐标航迹点输入；
- 恒定 RCS；
- FMCW 线性上扫频和脉冲 LFM；
- 显式 Tx、传播和 Rx 复基带链；
- 单站 1T1R；
- 热噪声或直接噪声功率；
- 距离处理、速度处理和二维 CA-CFAR；
- 真值、检测数据、中间数组和诊断图保存；
- 面向未来多通道的张量和接口。

初版不包含：

- 阵列测角和波束形成；
- MIMO 编码、调度和解码；
- Swerling RCS 起伏；
- 多径、遮挡、地杂波和大气衰减；
- 天线方向图；
- 距离迁移校正和高级参数估计算法；
- 实时处理；
- GUI 或 Web 界面。

## 11. 验收标准

- 两个示例脚本可以分别完成 FMCW 和 LFM 全链路仿真。
- 修改 Python Config 即可改变雷达、波形、目标、噪声和处理参数。
- 发射和接收数据均保留明确的通道维，1T1R 限制只存在于配置验证层。
- 所有坐标、径向速度和多普勒符号遵循本设计的统一约定。
- 处理模块只依赖信号和元数据，不依赖目标真值。
- 自动测试覆盖坐标、航迹、波形、传播、噪声、处理和输出边界。
- 项目能够输出配置快照、真值、检测列表、中间数据和三类诊断图。
